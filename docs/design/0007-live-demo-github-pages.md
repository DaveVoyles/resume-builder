# 0007 — Live sample/demo page on GitHub Pages

## Problem Statement

resume-builder's README makes a strong claim — "it's actually working for me" — backed by a
static screenshot of Dave's real, private dashboard. Prospective users can't interact with it,
and a screenshot alone doesn't prove the *generated* artifact (an interactive, searchable,
self-contained HTML tracker) actually works the way the README describes.

This plan adds a live, publicly hosted sample of that exact artifact — generated by the real
`renderHtmlTracker` renderer, from placeholder data for a fictional candidate ("Troy McClure"),
so visitors can click around a genuine dashboard before running the tool themselves.

## User Stories

1. As a prospective user browsing the README, I want to click a live demo link and interact with
   a real tracker dashboard, so I can evaluate the tool's actual output before installing
   anything.
2. As Dave, I want the demo to always be genuine renderer output (not a hand-maintained mockup),
   so it can never silently drift from what real users actually get.

## Testing Decisions

- **D1:** seam is `node scripts/check-workspace.js --workspace examples/demo-candidate` (existing schema/structure checker, already generic over `--workspace`) plus `node scripts/check-privacy.js` repo-wide — no new test framework needed, this is data authored against an already-validated schema.
- **D2:** seam is `tests/renderers/html-tracker.test.js` (unit-test the rendered HTML string for notice-present vs. notice-absent) and `tests/cli/build-tracker.test.js` (assert the `--notice` flag reaches the renderer). Both files already exist and follow `node --test`.
- **D3:** no unit-test seam (it's a workflow file) — verification is a local dry run of the exact build command before pushing (inspect the generated `index.html` in a browser), then `gh run watch` on the first real deploy after merge to confirm the Pages job goes green.
- **D5:** manual check — grep README for the new link before merge, and confirm the link resolves 200 once D3's first deploy has gone live.

## ⚠️ Irreversible Steps

None of the deliverables themselves are git-irreversible — all are additive (new data files, a
renderer option, a new workflow file, a README edit), fully revertible with a normal
`git revert`.

**One gated action, explicitly NOT pre-authorized by this plan's approval:** enabling GitHub
Pages in the repo's own Settings → Pages (Source: "GitHub Actions") is required for D3 to
actually publish anything. This is a repo/account-settings change, which — separately from
whether it's technically reversible (Pages can be turned back off) — requires explicit in-chat
confirmation at execution time under the standing safety protocol, or Dave flipping it on
himself. The orchestrator must pause and ask before doing this, even though everything else in
this plan is pre-authorized by approval.

## Out of Scope

- Modifying `examples/sample-candidate/` ("Alex Rivera") data — the demo workspace is new and
  separate.
- Rendering or linking to the other sample artifacts (resume DOCX sample, study-guide sample) on
  the live page — single-page scope only, per grilling decision.
- A custom domain/CNAME for GitHub Pages.
- Any change to onboarding-checklist logic itself — D1 simply omits the onboarding-state file so
  the existing opt-in behavior naturally renders no checklist.
